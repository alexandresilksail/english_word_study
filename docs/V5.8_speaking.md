# V5.8 口语（Speaking）+ 听力（Listening）

## 目标
实现口语练习闭环与听力素材复用，同时守住「没测就不给分」的诚实底线。

## 交付内容

### 服务层：`speaking.py`（顶层模块，非 `services/` 包）

三条通道，均为「适配器 + mock 默认」：

| 通道 | 环境变量 | mock 行为 |
|---|---|---|
| STT 语音识别 | `SPEECH_PROVIDER` / `SPEECH_API_KEY` | **明确不可用** → 前端切手动输入 |
| TTS 语音合成 | 同上 | **明确不可用** → 改用浏览器内置朗读 |
| 发音评分 | 同上 | 只算能算的维度，其余返回 `None` |

HTTP 走标准库 `urllib`（含**手写 multipart/form-data**），不引入 SDK。

### 口语流程
```
录音 →（可用时识别）→ 与参考句逐词对齐 → 词级纠错 → 评分 → 重练
```

若识别不可用，用户直接键盘输入 —— **功能仍完整可用，只是不假装识别成功**。

### API（`routes/speaking.py`，前缀 `/api/speaking`）
| 端点 | 方法 | 说明 |
|---|---|---|
| `/status` | GET | 三条通道可用性 + 可测/不可测维度 |
| `/score` | POST | `{text, reference, lang}` → 评分与词对齐 |
| `/transcribe` | POST | multipart 上传录音 |
| `/synthesize` | POST | 参考句朗读 |
| `/listening` | GET | 听力素材清单 |

未登录 401；参数缺失 422；无音频文件 422；套餐不足 403。

## 🧪 评分口径（诚实原则的核心）

| 维度 | 是否真实可测 | 依据 |
|---|---|---|
| **accuracy** | ✅ | `difflib` 词对齐后「说对的词 / 参考句词数」 |
| **vocabulary** | ✅ | 参考句内容词（去停用词）被覆盖的比例 |
| **fluency** | ❌ | 需音频时长 / 停顿特征 |
| **grammar** | ❌ | 需语法解析 |

> ### 为什么是 `None` 而不是 `0`
>
> `0` 会被用户读成「我的流利度极差」，而**真相是「没测」**。
> `None` 让前端显示「未评估 / —」，这才是诚实的表达。
>
> `overall` 只对**已测维度**求平均，不会被 `None` 稀释或当成 0。

页面在练习模式（Practice Mode）下会明确说明这一点。

## 🔊 听力素材：复用既有 2000 个 MP3

> **关键发现**：这 2000 个 MP3 挂在 **`Word`**（legacy 单词库）上，命名 `word.mp3`；
> 而 `ContentItem.surface` 多为短语与粤语词条，与之**几乎无交集**。
>
> 最初按 `ContentItem.surface` 猜文件名，**命中 0 个**。
> 改为走 `Word.audio` 后命中率 100%（生产库 2000/2000）。

- 逐条校验文件**真实存在**，绝不把必然 404 的链接交给前端
- 文件名做**路径穿越**（`../`）与后缀校验
- 粤语等无音频语种返回空列表，由前端显示空态

## 套餐
Speaking（含 `score` / `transcribe` / `synthesize` / `status`）属 **PRO**；
`listening` 三档通用。

## 安全
- 音频大小上限 `SPEECH_MAX_AUDIO_BYTES`（默认 8MB）
- 文本长度上限 `SPEECH_MAX_TEXT_CHARS`（默认 1000）
- 异常只记录类型，不回显 `Authorization`

## 已知限制
- 浏览器原生 `MediaRecorder` 不支持的机型无法录音，页面会明确提示并保留手动输入路径
- 浏览器语音合成的音色与可用性取决于用户系统，非本服务可控
