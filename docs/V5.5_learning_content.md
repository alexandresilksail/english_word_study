# V5.5 学习内容引擎 + 练习写入口

## 目标
把「课时」从静态内容展示，升级为**结构化四步学习流**，并建立掌握度的写入口。

## 交付内容

### 四步学习流（Learn → Practice → Quiz → Complete）
`app/templates/lesson.html` 重写为四个面板，由 `data-step` 标识：

| 步骤 | 内容 | 交互 |
|---|---|---|
| **Learn** | 闪卡，点击翻转看释义 | 纯前端翻转 |
| **Practice** | 自评回忆（会了 / 不会） | POST `/practice/submit` |
| **Quiz** | 四选一，选项由同课时干扰项构成 | POST `/practice/submit` |
| **Complete** | 完成本课，发放 XP | POST `/main.lesson_complete` |

### 干扰项生成（`routes/main.py :: lesson_view`）
- 从**同一课时**的其它条目取至多 3 个干扰释义
- **选项位置轮转**（`idx % len(opts)`）—— 否则正确答案恒在首位，
  用户会形成肌肉记忆，失去练习意义

### `POST /practice/submit`
- 支持**单条**与**批量**（`items[]`）
- JSON（含 `X-Requested-With`）返回 `{ok, data}`
- 表单提交回跳来源页 —— **渐进增强**，JS 失败也能用
- 未登录统一返回 **401 JSON**

### 新增模型：`ContentMastery`
「掌握到什么程度」的数据载体，与 `ReviewItem`（「何时复习」）解耦。
V5.5 只建表 + 落原始计数，V5.6 才升级为统一 0-4 计算。

### 写入口收口
> `mastery_service.record_practice()` 是所有学习结果的**唯一写入口**。
> 它先更新 ReviewItem（Leitner），再更新 ContentMastery 计数 / streak / 弱项。

## Mock 标注
**本版本不涉及外部 AI 调用**，无 mock 组件。

## 测试暴露的问题与设计决策

### 1. `services/` 包会遮蔽顶层 `services.py`
工程根目录已有顶层 `services.py`（Dashboard 统计）。最初把 mastery 服务放进
`services/` 包会导致整站崩溃。**已改回顶层 `mastery_service.py`**。

### 2. API 返回值曾把失败包在成功里
单条提交时 `_record_one` 失败也照样返回 `ok(payload)`，形成
`{"ok": true, "data": {"ok": false}}` 这种**自相矛盾的响应**。
已修正：单条失败必须返回顶层 `ok:false` + HTTP 422。

### 3. 配置了指定分支期遗留的 `notify_email` 迁移缺陷
`notify_email` 列在模型里有，但漏登记到 `schema_compat` 增量迁移清单，
导致老库（含生产）任何 `SELECT users` 直接报错。见 V5.6 文档。
