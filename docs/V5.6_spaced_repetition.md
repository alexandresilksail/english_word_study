# V5.6 间隔重复 + 统一掌握度 Mastery 0-4

## 目标
把 V5.5 的「只算练习」升级为综合三类证据的**统一掌握度 0-4**，
并修正复习时刻的两处不一致。

## 三类证据

| 类别 | 字段 | 说明 |
|---|---|---|
| A 练习证据 | `correct` / `wrong` → acc、`streak`、`review_count` | 日常练习表现 |
| B 课时小测 | `quiz_score`（0-100） | 课时内小测得分 |
| C 单元测试 | `unit_test_score`（0-100） | **权威性最高** |

## 判定规则

| level | 标签 | 条件 |
|---|---|---|
| 0 | New | 完全无记录 |
| 1 | Learning | 有任何学习记录 |
| 2 | Familiar | acc≥60 且 streak≥2 且 review≥2；或测验佐证 ≥60；或 review≥3 且 acc≥60 |
| 3 | Strong | acc≥80 且 streak≥3 且 review≥3；或测验佐证 ≥75 且 review≥2；或单元测试 ≥75 |
| 4 | Mastered | 练习到位（acc≥90/streak≥5/review≥5）**且**测验佐证 ≥85；或单元测试 ≥95 且 review≥3 |

### 为什么 Mastered 要求测验佐证
只看练习计数的话，**刷练习题量就能把还没真掌握的内容刷成「已掌握」**。
加一道权威测验门槛，是为了让「已掌握」这个标签名副其实。

### 关键语义：0 表示「未测验」
`quiz_score` / `unit_test_score` 的 **0 表示没测过**（沿用既有默认值语义）。
因此这两个分数**只作正向证据**抬高掌握度，**绝不倒扣**；
负向证据统一走 `wrong_count` / `weak`。

> 否则「没测过」会被误判成「测得很差」。这条由
> `test_zero_score_means_not_tested_never_penalises` 锁定。

## 修复：复习时刻的单一真源

**问题**：V5.5 在 `ContentMastery` 与 `ReviewItem` **各算一次**间隔。
两者虽初始值相同，但推算口径不同，**随使用会缓慢分叉**，最终出现
「复习页说到期了、实际安排不在」的不一致。

**修正**：`record_practice()` 现在**直接搬运** `ReviewItem.next_review_at`，
让 Leitner 队列成为复习时刻的唯一真源。

```
record_practice()
  ├─ record_result(...)          → 更新 ReviewItem + next_review_at（Leitner）
  └─ m.next_review_at = rev.next_review_at   ← 搬运，不自算
```

由 `test_next_review_at_mirrors_review_item` 锁定一致性。

## 修复：`notify_email` 漏登记迁移

`notify_email` 在 `models.py` 里存在，但**漏登记到 `schema_compat._EXTRA_COLUMNS`**。
后果是老库（含生产 `instance/` 库）任何 `SELECT users` 直接抛
`no such column: users.notify_email`。

**这是真实生产隐患，不是测试问题** —— 生产上的表现是登录 / 查询全面失败。
已补登记，并新增 `bool_true` DDL 类型（默认 1）。

## 单元测验 → 掌握度闭环

`unit_test_service.grade()` 判分后，把逐题结果经
`mastery_service.record_unit_test_results()` 并入掌握度：

- 每个被考到的内容按 `correct` 走 `record_practice(mode="unit_test")`
  —— 单元测验是一次**真实曝光**，同样进 Leitner 队列
- 整份测验的 `accuracy` 写入 `unit_test_score`，作为该条目的权威证据

> **该写入整体包 `try`**：掌握度属派生数据，写失败绝不能让用户丢掉
> 已算好的判分结果与单元解锁。由
> `test_unit_test_grade_survives_mastery_write_failure` 锁定。
